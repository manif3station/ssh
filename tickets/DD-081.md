## Title

Add governed `ssh.bridge` runtime, tests, and docs.

## Method

TDD

## Problem

`cli/bridge` existed only as a manually added script, so it was outside the `ssh` skill's governed ticket flow, test suite, and user-facing documentation. It also still carried one-off runtime assumptions instead of cleanly reusing the skill's managed ssh-agent behavior.

## Acceptance

- `dashboard ssh.bridge <ssh server> [remote-forward-port] [reconnect-seconds]` is part of the `ssh` skill release surface
- bridge reuses the skill-managed ssh-agent flow and the default `~/.ssh/id_ed25519` identity
- hosts ending in `.b` accept an optional remote-forward port argument and add `RemoteForward <port> localhost:22`, `ExitOnForwardFailure=yes`, `ServerAliveInterval=60`, `SessionType=none`, and `RequestTTY=no` through SSH command-line options
- bridge runtime and tests pass with the rest of the `ssh` skill suite
- Docker tests and `100%` statement and subroutine coverage pass for `lib/SSH/Add.pm` and `lib/SSH/Bridge.pm`
- docs, changelog, commit, and push are completed
